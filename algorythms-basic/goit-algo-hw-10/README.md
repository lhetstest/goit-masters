# Касова система: порівняння алгоритмів видачі решти

Набір монет: `[50, 25, 10, 5, 2, 1]`

---

## Алгоритми

### `find_coins_greedy` — Жадібний алгоритм

На кожному кроці обирає найбільший доступний номінал і бере максимальну кількість таких монет, потім переходить до наступного.

```
Для суми 113:
  50 × 2 = 100  → залишок 13
  10 × 1 = 10   → залишок 3
   2 × 1 = 2    → залишок 1
   1 × 1 = 1    → залишок 0
Результат: {50: 2, 10: 1, 2: 1, 1: 1}
```

**Складність за часом:** O(k), де k — кількість номіналів (константа 6) → **фактично O(1)**.  
**Складність за пам'яттю:** O(k) → **O(1)**.

---

### `find_min_coins` — Динамічне програмування

Будує таблицю `dp[0..amount]`, де `dp[i]` — мінімальна кількість монет для суми `i`. Для кожного значення перебирає всі номінали і вибирає оптимальний.

```
dp[0] = 0
dp[i] = min(dp[i - coin] + 1) для кожної монети coin ≤ i
```

Додатково зберігається масив `coin_used[i]` для відновлення складу монет.

**Складність за часом:** O(amount × k) → **O(n)**, лінійно залежить від суми.  
**Складність за пам'яттю:** O(amount) → **O(n)**.

## Висновки

### 1. Ефективність при великих сумах

Жадібний алгоритм **у мільйони разів швидший** при великих сумах. Його час виконання залишається сталим (~0.0002 мс) незалежно від суми — він завжди виконує рівно 6 ітерацій. ДП зростає **лінійно**: збільшення суми вдесятеро збільшує час вдесятеро (від 0.02 мс до 418 мс при зростанні суми в 10 000 разів).

### 2. Якість результату

Для набору `[50, 25, 10, 5, 2, 1]` обидва алгоритми дають **однакову кількість монет**. Це закономірно: такий набір є *канонічним* — він спеціально влаштований так, щоб жадібний вибір завжди давав глобальний оптимум.

### 3. Коли жадібний алгоритм не підходить

При довільному наборі монет жадібний може дати неоптимальний результат:

| Набір монет | Сума | Жадібний        | ДП (оптимум)  |
|-------------|------|-----------------|---------------|
| [6, 4, 1]   | 8    | 6+1+1 = 3 монети | 4+4 = 2 монети |
| [7, 3, 2]   | 6    | немає рішення   | 3+3 = 2 монети |

У таких випадках ДП — єдиний коректний варіант.

### 4. Рекомендації щодо вибору

| Ситуація | Рекомендація |
|---|---|
| Стандартні грошові системи (UAH, EUR, USD) | **Жадібний** — O(1), результат оптимальний |
| Довільний або нестандартний набір номіналів | **ДП** — гарантує мінімум |
| Великі суми зі стандартними монетами | **Жадібний** — миттєво, ДП може займати сотні мс |
| Велика кількість запитів в реальному часі | **Жадібний** — підходить для касових систем з будь-яким навантаженням |
| Задачі оптимізації з обмеженнями | **ДП** — єдиний варіант |

### Підсумок

Для задачі касового апарату з набором `[50, 25, 10, 5, 2, 1]` **жадібний алгоритм є безумовно кращим вибором**: він дає оптимальний результат за O(1) часу та O(1) пам'яті. ДП доцільний лише тоді, коли набір монет не є канонічним і потрібна гарантована мінімізація кількості монет.

# Обчислення інтеграла методом Монте-Карло

## Завдання

Обчислити визначений інтеграл функції **f(x) = x²** на відрізку **[0, 2]** методом Монте-Карло та порівняти результат з аналітичним розв'язком і функцією `scipy.integrate.quad`.

## Метод Монте-Карло

Суть методу — генерація великої кількості випадкових точок у прямокутнику `[a, b] × [0, y_max]` і підрахунок частки точок, що потрапили під криву:

```
I ≈ (b − a) × (1/N) × Σ f(xᵢ)
```

де `xᵢ` — рівномірно розподілені випадкові числа на `[a, b]`.

## Реалізація

```python
import numpy as np

def f(x):
    return x ** 2

a, b = 0, 2
N = 1_000_000

np.random.seed(42)
x_rand = np.random.uniform(a, b, N)
result = (b - a) * np.mean(f(x_rand))
```

## Результати

| Метод | Значення |
|---|---|
| Метод Монте-Карло (N = 1 000 000) | **2.668955** |
| `scipy.integrate.quad` | **2.666667** |
| Аналітично (x³/3 від 0 до 2) | **2.666667** |

Аналітичне значення:

```
∫₀² x² dx = [x³/3]₀² = 8/3 ≈ 2.666667
```

Відхилення методу Монте-Карло від точного значення: **≈ 0.0023** (0.086%).

## Висновки

1. **Точність методу** підтверджена: при N = 1 000 000 відхилення від точного значення становить менше **0.1%** — достатньо для практичних задач.

2. **Порівняння з `quad`**: функція `scipy.integrate.quad` дає майже машинну точність (похибка ~3×10⁻¹⁴), тоді як метод Монте-Карло є стохастичним і збігається зі швидкістю O(1/√N). При збільшенні N у 100 разів точність зростає приблизно в 10 разів.

3. **Практична придатність**: метод Монте-Карло найбільш корисний для **багатовимірних** інтегралів, де класичні чисельні методи стають надто дорогими. Для одновимірних задач `quad` є кращим вибором.

4. **Відтворюваність**: фіксація `np.random.seed(42)` забезпечує відтворюваний результат між запусками.
